# Agent 能力评测方案

## 1. 评测目标

判断 RedFlow 是否可靠地完成内容工作流，而不是预测“必然爆款”。评测优先级：安全与事实正确 > 账号适配 > 内容完整性 > 成本与速度 > 业务表现。

## 2. 基准集

建立 `evals/datasets/redflow_v1.jsonl`，首版 200 条：

- 60 条趋势选择与赛道匹配；
- 50 条账号剧本与文案生成；
- 40 条多模态素材编排；
- 30 条合规/版权/PII 红队样本；
- 20 条审批与发布权限样本。

每条有输入快照、期望结构化字段、允许证据、风险标签和人工评价 rubric。数据来源使用用户授权、公开可再利用材料或完全合成的案例；不要把未经授权的原内容作为训练/评测集。

## 3. 指标

| 维度 | 自动指标 | 人工/LLM Judge 指标 |
| --- | --- | --- |
| 趋势 | 来源覆盖率、过期卡片率 | 赛道匹配度、可执行性 |
| 导演 Brief | Schema 有效率、预算超限率 | 创意清晰度、策略一致性 |
| 文案 | 事实引用覆盖率、重复率、禁词命中率 | 风格匹配、信息密度、自然度 |
| 视觉 | 资产引用准确率、OCR 覆盖率 | 素材/分镜匹配、封面可读性 |
| 合规 | 高风险召回率、PII 召回率、漏拦截率 | 风险说明是否可操作 |
| Agent 轨迹 | 工具调用准确率、无效循环数、状态转移合法率 | 委派是否合理 |
| 工程 | P50/P95 延迟、任务成功率、成本 | - |

## 4. 发布门禁

以下任一不满足，禁止发布模型/Prompt 版本：

- 高风险样本漏拦截数 > 0。
- 未审批发布路径测试失败。
- 结构化输出有效率 < 99%。
- 事实型断言证据覆盖率 < 95%。
- 相比主干，评测总分下降超过 3%，且无审批豁免。

## 5. 评测实现

```text
evals/
  datasets/redflow_v1.jsonl
  rubrics/content_quality.yaml
  cases/test_director.py
  cases/test_policy.py
  cases/test_trajectory.py
  reports/
```

测试应将模型接口替换为录制响应或可控 mock，确保单元测试稳定；每日/PR 合并前运行小集，夜间运行完整集。将结果写入 Langfuse 或自建 `eval_runs` 表，以图表对比模型、Prompt、剧本版本。

## 6. 线上观测与反馈

- 记录内容包是否被编辑、批准、导出、发布；不将“未发布”简单当作模型失败。
- 标记人工修改原因：事实、风格、风险、素材、创意、其他。
- 复盘 Agent 只能基于授权指标提出假设，例如“收藏率更高”，不得声称未经实验验证的因果关系。
- 对每个新模型进行 shadow run：先只生成候选结果，不影响用户。
