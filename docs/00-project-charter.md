# RedFlow 项目章程

## 1. 愿景

RedFlow 是一个面向个人创作者、小品牌与小型内容团队的多模态内容运营 Agent。系统将外部趋势、账号策略、用户自有素材和可验证的业务事实，转化为可审核、可编辑、可辅助发布、可复盘的内容包。

核心价值不是“用 AI 写一篇笔记”，而是降低内容运营中反复发生的决策成本：今天做什么、为什么做、怎么表达、素材是否合适、是否安全、发布后学到了什么。

## 2. 目标用户

| 用户 | 核心痛点 | 首版收益 |
| --- | --- | --- |
| 个人创作者 | 选题和素材整理耗时、风格难稳定 | 一次输入得到符合人设的完整图文方案 |
| 本地生活商家 | 没有专职运营、真实素材很多但不会用 | 将门店/商品素材编排为可发布内容 |
| 小型品牌团队 | 多人协作、审核和品牌一致性难保障 | 通过剧本、审批与资产权限统一内容生产 |
| 代运营/MCN | 多账号内容重复、交付不可追踪 | 内容日历、Trace、风险报告和客户审阅 |

## 3. 问题陈述

内容生产通常被割裂为热点搜索、脑暴、拍摄、文案、审核、发布和复盘等工具。创作者在工具间复制粘贴，缺少对账号人设、素材版权、品牌口径和历史表现的统一记忆。单纯的文案生成无法解决“内容决策”和“安全交付”。

## 4. 产品原则

1. **真实素材优先**：优先编排用户资产，生成式媒体只作补充。
2. **人类最终决策**：高风险内容和任何对外发布均可被人工控制。
3. **证据优先**：热点、商品事实、政策与复盘建议必须带来源和时间。
4. **结构化交接**：Agent 之间传递 JSON 合同，不依赖隐式长文本。
5. **平台合规优先**：不设计绕过账号、反爬、验证码、频控或社区规则的功能。
6. **先可测后扩张**：每新增 Agent 能力都要有可重复的评测集和观测指标。

## 5. MVP 成功标准

在一个明确垂类（建议：本地生活咖啡/轻食或知识型个人 IP）中达到：

- 用户从选题到获得可审核图文内容包的中位耗时小于 10 分钟。
- 至少 70% 的试用内容包被用户保留、编辑或进入审核，而非直接丢弃。
- 高风险内容未经过审核进入发布队列的比例为 0。
- 事实型断言均能关联到用户资料或标记为“待核实”。
- 评测集中，账号风格一致性和内容完整性人工评分不低于 4/5。

## 6. MVP 范围

### In scope

- 一个工作区内多账号画像、剧本、品牌规则和素材库。
- 趋势卡片导入与打分；来源为公开允许访问或用户授权数据。
- 创意导演 Agent 调度选题、文案、视觉方案与合规检查。
- 图文内容包、封面文案、分镜、话题、发布建议。
- 图片理解（OCR、标签、质量与重复检测）和视频分镜。
- 审核队列、内容日历、草稿导出、辅助发布适配层。
- Trace、成本、延迟、离线评测。

### Out of scope

- 自动注册/登录账号、验证码绕过、模拟点击发布。
- 批量矩阵运营、刷赞刷评、虚假种草或诱导互动。
- 无授权的受限数据采集、私密内容访问。
- 医疗、金融、法律等高风险建议型内容。
- 自研基础大模型或从零训练视频生成模型。

## 7. 商业化假设

先以“一个垂直赛道的内容工作台”验证留存，再扩展：

- Free：1 个账号、有限内容包、手动导出。
- Creator：剧本库、多模态素材和内容日历。
- Team：协作、审批、品牌资产、数据回收与权限。
- Studio/Enterprise：多租户、私有部署、审计、官方授权连接器。

## 8. 风险登记

| 风险 | 后果 | 缓解 |
| --- | --- | --- |
| 平台 API 能力变化 | 自动发布不可用 | 抽象 Publisher；MVP 以草稿/辅助发布为主 |
| 热点数据质量不足 | 选题失真 | 保存来源、时间与置信度；支持人工导入 |
| 生成内容同质化 | 用户体验差、平台风险 | 账号记忆、相似度阈值、实验化创意角度 |
| 版权/肖像权风险 | 法律与品牌风险 | 资产许可元数据、审核 Gate、默认拦截未知来源 |
| 模型幻觉 | 错误营销承诺 | 事实 RAG、结构化断言校验、人工审批 |
| 成本失控 | 小团队不可持续 | 模型分级、预算、缓存、素材重用 |
